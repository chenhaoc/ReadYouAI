# 后台预生成摘要设计

日期：2026-04-23

## 目标

- 缩短开启自动摘要订阅的首开等待时间。
- 在不改变现有订阅级 `自动摘要` 入口的前提下，为 AI 摘要增加后台预生成能力。
- 后台默认处理本次同步新增文章，并支持手动或同步后按上限补齐历史未读摘要。

## 非目标

- 不改现有阅读页手动摘要和前台自动摘要的交互。
- 不绕过订阅级 `自动摘要` 范围控制，不对未授权订阅源批量生成摘要。
- 不引入新的订阅级后台摘要开关。

## 产品语义

- 保留订阅级 `自动摘要`，表示该订阅允许自动生成摘要。
- AI 设置页全局开关 `后台预生成摘要` 作为后台任务总控。
- `每次最多预生成` 控制单个后台 worker run 最多生成的摘要篇数，选项为 `10 / 25 / 50 / 100 / 不限`，默认 `25`。
- `补齐历史未读摘要` 是手动入口：按最新优先把未读且无摘要的文章加入后台队列。
- `同步后补齐历史未读摘要` 是激进开关：每次同步后也会按同一上限补齐旧未读文章。
- 后台预生成生效条件：
  - 全局 `后台预生成摘要` 开启。
  - 订阅 `自动摘要` 开启。
  - AI Base URL 和 API Key 已配置。
- 阅读页继续保留前台兜底：
  - 后台未生成完成时，打开文章仍可按现有逻辑触发摘要。

## 触发时机

- sync 完成后仍先执行现有 `ReaderWorker` 全文抓取。
- 全文抓取完成后再执行新的后台摘要 worker。
- 后台摘要优先使用全文缓存；若全文抓取失败，则退回文章已有 `rawDescription` 或 `shortDescription`。

## 范围控制

- 本次 sync 新入库文章：按订阅级 `自动摘要` 过滤后入队，并受 `每次最多预生成` 上限影响。
- 手动补齐历史未读：只扫描当前账号下 `未读 + 无 aiSummary + feed.isAutoSummary = true` 的文章，按文章发布时间新到旧入队。
- 同步后自动补齐历史未读：仅在 `同步后补齐历史未读摘要` 开启时触发，规则与手动补齐一致。
- `不限` 只取消单次篇数上限，不取消全局开关、订阅级开关、AI 配置和 worker 失败重试边界。

## 数据设计

- 新增持久化队列表 `pending_ai_summary_task`。
- 字段：
  - `articleId`：主键，同时关联 `article.id`。
  - `accountId`：用于按同步账户消费任务。
  - `createdAt`：入队顺序，手动/自动补齐时按新文章优先写入。
  - `attemptCount`、`lastAttemptAt`、`nextRunAt`：用于网络失败退避重试。
- `articleId` 唯一，重复 sync 或重复补齐不重复入队。

## 执行链路

- `SyncWorker` 完成同步后串联：
  - `ReaderWorker`
  - `AiSummaryPrecomputeWorker`
  - `WidgetUpdateWorker`
- `SyncWorker`、`ReaderWorker`、`AiSummaryPrecomputeWorker` 之间透传 `accountId`。
- 各 RSS 同步实现拿到“本次新入库文章”后，按条件写入后台摘要队列。
- 若开启 `同步后补齐历史未读摘要`，`SyncWorker` 在 post-sync 链路前额外把历史未读缺失摘要文章按上限入队。
- 手动 `补齐历史未读摘要` 直接入队并启动一次 `AiSummaryPrecomputeWorker`。

## Worker 行为

- `AiSummaryPrecomputeWorker` 每次从队列取小批量任务，最多并发 3。
- 单次 worker run 最多处理 `每次最多预生成` 配置的篇数，默认 25；选择 `不限` 时会继续消费当前可运行队列。
- 每个任务执行前再次检查：
  - 文章是否仍存在。
  - 文章是否已有 `aiSummary`。
  - 全局开关是否仍开启。
  - 所属 feed 是否仍开启 `自动摘要`。
- 满足跳过条件时直接删除队列项。
- 成功生成摘要后写回 `article.aiSummary`，并删除队列项。

## 失败策略

- 网络类或未知失败：单篇任务按 `nextRunAt` 退避重试，达到上限后丢弃任务。
- 单篇文章的业务错误：记录日志并删除该任务，避免整批阻塞。
- 后台任务不弹前台 toast。

## 并发与竞态

- 后台摘要最大并发为 3。
- 若用户在后台任务完成前打开文章，前台兜底摘要可以先执行。
- 后台 worker 在请求前再次检查 `aiSummary`，尽量避免重复调用。
- 第一版不额外引入“摘要生成中”持久化状态位。

## UI 改动

- AI 设置页保留 `后台预生成摘要` 开关。
- 新增 `每次最多预生成` 单选项：`10 / 25 / 50 / 100 / 不限`，默认 25。
- 新增 `补齐历史未读摘要` 手动入口，点击后确认并启动一次后台补齐。
- 新增 `同步后补齐历史未读摘要` 开关，用于同步后自动补齐历史未读缺失摘要文章。
- 保留现有全局 `自动摘要` 设置，用作“新订阅默认启用自动摘要”的默认值，不改变其语义。
- 不新增订阅级后台开关。

## 验证点

- 本次新增文章按上限入队并按新文章优先。
- 手动补齐只选择未读、无摘要且订阅源开启自动摘要的文章。
- 同步后补齐只有开关开启才触发。
- 队列不重复写入同一文章。
- `ReaderWorker` 后才开始后台摘要。
- 全局开关关闭或 feed 开关关闭时不生成。
- 前台先生成后，后台消费能正确跳过。
- 后台失败可重试，单篇坏数据不阻塞后续任务。

## 风险

- `ReaderWorker` 当前依赖账户上下文，后台摘要链路需要显式透传 `accountId` 以避免多账户串错。
- 前后台极端竞态下仍可能出现少量重复请求；若后续观察到 token 浪费，再考虑引入持久化中的“处理中”状态。
