# 阅读页 AI 问答抽屉设计

## 背景
阅读页原本只有 AI 摘要，适合快速概览，但不适合围绕局部段落、专有名词和文章背景做连续追问。当前实现已经在阅读页接入专属 AI 问答抽屉，并补齐会话持久化、选区预填、快捷提问和 Markdown 回复渲染。

## 已落地目标
- 在阅读页顶栏提供 `AI 问答` 入口。
- 用底部抽屉承接围绕当前文章的多轮问答。
- 打开抽屉时优先读取当前选中文本，并在抽屉内展示选区卡片。
- 提供 `全文上下文` 开关和四个快捷提问按钮。
- 按 `articleId` 保留问答历史，关闭抽屉后可恢复。
- 使用 WebView 渲染 Markdown 回复，避免复杂内容在原生文本中丢失层级。

## 当前界面结构

### 阅读页顶栏
```text
[返回]                    [AI 摘要] [AI 问答]
```

### AI 问答抽屉
```text
┌──────────────────────────────────────────────┐
│ AI 问答                       [新会话] [关闭] │
│ [全文 开/关]                  已选中 N 字     │
│                                              │
│ [解释这篇文章] [解释这段话]                  │
│ [给出相关背景] [介绍一下]                    │
│                                              │
│ [选中文本预览卡片，可清除]                   │
│                                              │
│ [历史消息列表 / AI Markdown 回复]            │
│                                              │
│ [输入框.................................][发送]│
└──────────────────────────────────────────────┘
```

## 交互设计

### 打开时机
- 阅读页点击 `AI 问答` 后，先抓取当前选区，再打开抽屉。
- 选区为空时仍可打开抽屉，但 `解释这段话` 会禁用。

### 抽屉头部
- 标题右侧提供两个动作：
  - `新会话`：清空当前文章的历史消息。
  - `关闭`：关闭抽屉，不清除当前文章历史。
- 第二行同时展示全文上下文开关和选区状态。

### 快捷提问
- `解释这篇文章`
- `解释这段话`
- `给出相关背景`
- `介绍一下`

点击后直接发起提问，不只填充输入框。

### 会话持久化
- 问答记录按文章隔离。
- 关闭并重新打开同一篇文章时，自动恢复历史。
- 切换文章时切换到该文章对应的会话。

## 上下文拼装

### 请求上下文
- 文章标题
- 订阅源名称
- 文章链接
- 文章正文
  - 仅在 `全文上下文` 开关开启时附带
- 选中文本
  - 若存在，则作为优先解释对象
- 最近若干轮历史消息
- 本轮用户输入或快捷问题

### 提示词配置
- 复用全局 AI 服务配置：`baseUrl / apiKey / model`。
- 独立提供问答提示词配置，不和摘要提示词混用。
- 提示词配置页已按当前问答场景收敛说明和默认文案。

## 渲染与实现

### UI 组件
- `AiChatSheet` 负责抽屉整体布局。
- `SelectedSnippetCard` 负责展示并清除当前选区。
- `AiChatBubble` 负责区分用户和助手消息。
- Markdown 回复通过内嵌 `WebView` 渲染。

### WebView 渲染链路
- 增加内容高度回传，保证抽屉内消息列表能随 Markdown 实际高度布局。
- Markdown 回复样式已按当前阅读环境调整，避免默认网页观感过重。
- 回复渲染与历史恢复走同一条消息通路。

## 非目标
- 当前版本不支持流式输出和中途停止生成。
- 不支持跨文章共享同一会话。
- 不做抽屉内重新选区。
- 不做会话导出或跨设备同步。

## 验证要点
- 打开抽屉时先抓取选区，再展示抽屉。
- 同一文章关闭重开后，历史仍能恢复。
- 清空会话只影响当前文章。
- Markdown 回复中的列表、强调和段落层级在抽屉内可正常显示。
- 全文上下文开关关闭后，请求中不再附带全文正文。
