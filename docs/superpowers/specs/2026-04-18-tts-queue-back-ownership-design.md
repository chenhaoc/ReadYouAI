# TTS 播放列表返回响应设计

## 目标
修复共享 TTS 播放列表在订阅源页和阅读页中无法优先响应系统返回的问题，确保只要播放列表处于打开态，系统返回就先关闭播放列表。

## 问题复盘
- TTS 播放列表是根级共享能力，入口来自订阅源、信息流和阅读页。
- 早期实现把“返回时关闭播放列表”的职责放在页面层和导航层兜底。
- 这种写法在信息流页看起来正常，但在订阅源和阅读页里会被更内层的返回消费方抢先处理，最终表现为先返回上一级，而不是先关闭播放列表。
- AI 问答之所以没有同类问题，是因为它使用 `ModalBottomSheet`，返回由抽屉自身消费。

## 最终方案
将根级 TTS 播放列表宿主改为 `Material3 ModalBottomSheet`，让播放列表自身成为 dismiss owner。

这意味着：
- 播放列表的返回关闭语义由 sheet 自己处理。
- 页面和导航层不再抢占 queue 专属返回。
- `isQueueOpen` 只保留给 UI 状态使用，不再承载返回优先级逻辑。

## 当前实现

### 根级宿主
- 宿主位于 `AppEntry`。
- 使用 `rememberModalBottomSheetState(skipPartiallyExpanded = true)` 管理播放列表显示状态。
- 通过 `isQueueSheetMounted` 控制 sheet 是否挂载，避免关闭动画被直接截断。
- `closeQueue()` 统一负责 `hide -> 卸载 -> 可选后续动作` 的时序。

### 打开与关闭
- 任一页面调用 `onOpenQueue` 时，先挂载 sheet，再执行 `show()`。
- 点击当前播放文章时，先执行 `closeQueue()`，再导航到文章详情。
- 系统返回由 `ModalBottomSheet` 优先消费并关闭自己。

### 页面层清理
- 删除阅读页、订阅源页和根导航中为 queue 专门添加的返回兜底。
- 删除已经证明无效的 queue-priority back 方案。
- 保留 `isQueueOpen` 给底栏高亮、悬浮按钮和局部 UI 判断使用。

## 为什么不用旧方案
- 继续在页面层挪 `BackHandler`，无法稳定解决多层导航竞争。
- 把返回 ownership 收回到 M2 `BottomDrawer` 理论上可行，但仍属于外围兜底，不如直接让 modal sheet 自己消费返回干净。
- 当前根级 M3 `ModalBottomSheet` 方案已经实测修复订阅源、信息流和阅读页三处返回行为。

## 当前 UI 取舍
- 根级播放列表外层补回了横向和底部安全留白，避免圆角屏幕吃字。
- 留白相对旧抽屉壳体收敛，兼顾内容密度和安全区。
- 播放卡片容器色允许沿用新版视觉，不强制回退到旧样式。

## 验证要点
- 信息流页打开播放列表后，返回先关闭播放列表。
- 订阅源页打开播放列表后，返回先关闭播放列表。
- 阅读页打开播放列表后，返回先关闭播放列表。
- 从播放列表打开当前文章时，先关闭播放列表，再跳转文章。
- 播放列表标题、当前播放卡片和普通队列项在新宿主下布局正常。
