# 本地 RSS 视频控件清洗设计

## 背景

部分微信公众号文章在 RSS 摘要 HTML 中会混入整段视频播放器控件文本，例如：

- `已关注`
- `关闭`
- `观看更多`
- `倍速播放中`
- `0.5倍`
- `超清`
- `流畅`
- `继续观看`
- `视频详情`

这些文本会直接污染本地 RSS 文章入库后的正文摘要，也会影响 TTS 朗读内容。

在本轮收敛后，范围只保留本地 RSS 路径，不再同时处理第三方同步服务、阅读渲染增强或旧数据兼容。

## 目标

- 仅解决本地 RSS 入库阶段的视频控件噪音清洗。
- 保留视频封面图。
- 保留播放图标提示，让视频封面在阅读页里仍然明显可识别。
- 尽量保留原始视频图片已有的跳转链接。
- 当视频 widget 本身没有可保留的独立链接时，回退为文章原文链接。
- 让 TTS 使用清洗后的 HTML，而不是朗读播放器控件文本。

## 非目标

- 不处理 FreshRSS、Google Reader、Fever 等第三方同步链路。
- 不兼容已经按旧逻辑入库的历史数据。
- 不把这次改动扩展到 AI 摘要、AI 翻译、阅读统计或全文解析路径。

## 问题结构

当前观察到的本地 RSS 视频噪音结构主要有两类：

### 1. 媒体邻域噪音

正文中先出现视频配图或链接包裹的视频配图，后面紧跟一串控件文本块，例如：

- 状态词块：`已关注 关注 直播 分享 赞 关闭`
- 播放状态块：`0:00 / 00:06 切换横屏模式 继续播放`
- 倍速与清晰度块：`倍速播放中 0.5倍 1.0倍 超清 流畅`
- 行为入口块：`继续观看`、`视频详情`

### 2. 微信视频 widget

在 `content:encoded` 中直接嵌入 `span.video_iframe.rich_pages` 或 `mp-common-videosnap` 这类完整视频组件，组件内部既有封面信息，也有播放器控件 DOM。

## 最终方案

新增共享 HTML 清洗器 `VideoNoiseCleaner`，并配合阅读渲染层共同完成以下三件事：

1. 把微信视频 widget 归一化为“可显示且可点击的封面图”。
2. 删除媒体节点前后连续的播放器控件噪音块。
3. 让阅读页把这类封面按视频处理，而不是按普通图片处理。

### 1. widget 归一化

对于 `span.video_iframe.rich_pages` 和 `mp-common-videosnap`：

- 提取 `video[poster]` 或 `data-cover`、`data-feedcoverurl`、`data-feedfullcoverurl`、`data-feedthumburl` 中的封面图；
- 输出带视频语义标记的封面图；
- 如果当前文章链接可用，则用文章原文链接包裹封面图；
- 删除紧随其后的微信 placeholder。

归一化后的目标是：

- 阅读页还能看到封面图；
- 跳转行为尽量保留；
- 不再保留整棵视频播放器 DOM。

### 2. 邻域噪音删除

清洗器只在媒体邻域工作，不做全局关键词替换。

规则如下：

- 以 `img`、`video`、`iframe`、`figure` 或包含这些媒体的空容器作为锚点；
- 向前和向后扫描有限数量的兄弟节点；
- 如果一段连续节点表现出明显的播放器控件特征，则整段删除；
- 保留媒体节点本身以及之后的真实正文。

### 控件判定信号

判定依据由以下信号组合而成：

- 控件关键词密集命中；
- 倍速、时间、进度等播放模式文本；
- `control`、`player`、`video-info`、`sr-only` 等 class/id 提示；
- 表单、按钮等控件型后代节点。

只有当信号足够集中，且发生在媒体邻域时，才执行删除。

### 3. 阅读渲染

对被清洗器标记为视频封面的内容：

- NativeComponent 显示播放图标提示；
- WebView 显示播放图标提示；
- 点击时打开原文链接；
- 不再按普通图片预览处理。

这样可以保留前面已经验证通过的“封面图 + 播放提示 + 点击跳转原文”效果。

## 接入点

### 本地 RSS 入库

在 [RssHelper.kt](/Users/hao.chen/工作文档/Work/readyou/ReadYou/app/src/main/java/me/ash/reader/infrastructure/rss/RssHelper.kt) 的 `buildArticleFromSyndEntry(...)` 中：

- 对 `content:encoded` 或 `description` 先执行 `VideoNoiseCleaner.cleanHtml(...)`；
- 将结果写入 `rawDescription`；
- 基于清洗后的 HTML 生成 `shortDescription`。

### TTS

TTS 保持在本次最小闭环内：

- `htmlToPlainText(...)` 先清洗 HTML，再转纯文本；
- `resolvePlayableHtmlContent(...)` 返回可播放 HTML 前，先执行同样的清洗。

这样可以保证本地 RSS 视频控件文本不会被 TTS 朗读。

## 跳转链接策略

### 已有链接的媒体

如果视频配图原本就是 `<a><img></a>` 结构：

- 清洗器只删除周围噪音块；
- 原始图片和原始跳转链接保持不变。

### 微信 widget 替换后的媒体

如果原始 widget 没有可直接保留的独立媒体链接：

- 使用文章原文链接包裹封面图；
- 至少保留“点击图片能回到原文”的行为。

### WebView 行为

`WebView` 默认会把图片点击劫持为“查看大图”。本次只对视频封面图做最小例外：

- 如果图片被视频封面链接包裹，则不再注入图片预览点击；
- 让它走原有链接导航；
- 普通图片行为不变。
