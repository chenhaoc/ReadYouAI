# 摘要模式设计

日期：2026-04-24

## 目标

- 为通勤、散步和碎片时间里的科技新闻收听提供一个低操作成本入口。
- 在现有 TTS 播放列表基础上增加 `全文模式 / 摘要模式` 切换。
- 摘要模式只朗读已有 AI 摘要，避免默认朗读全文导致信息密度过低。
- 保留旧摘要列表结果，避免切换模式或误触时覆盖已生成的摘要队列。

## 非目标

- 不在第一版做聚类去重或跨来源主题合并。
- 不为没有摘要的文章自动生成摘要。
- 不改变现有阅读页、列表页的单篇 `加入播放列表 / 立即播放` 行为。
- 不新增一套独立播放器；继续复用现有 TTS 播放、通知栏和耳机控制链路。

## 已确认产品规则

- 摘要来源支持配置多个订阅分组和多个单独订阅源。
- 只扫描摘要来源下的未读文章。
- 只加入已有 AI 摘要的文章；没有摘要的文章跳过。
- 默认摘要时长为 30 分钟，并提供配置项。
- 默认排序为新文章优先。
- `听完摘要后标记为已读` 做成开关，默认关闭。
- 全文队列和摘要队列分开保存，共用底层 TTS 播放服务。

## 交互设计

### 播放列表面板

将现有播放列表标题改成可切换模式的标题：

- 全文模式：`全文模式 ▾`
- 摘要模式：`摘要模式 ▾`
- 下拉选项：
  - `全文模式`
  - `摘要模式`

### 全文模式

- 保持现有播放列表行为。
- 继续显示当前播放卡片、定时播放、清空、队列项排序、删除和打开文章。
- 普通文章加入队列时只影响全文模式队列。

### 摘要模式空状态

切到摘要模式且没有旧结果时，播放卡直接提示：

- 标题：`还没有摘要列表`
- 提示：`请点击右上角生成`

右上角保留刷新图标；点击后打开生成方式弹窗。

生成方式弹窗：

- 标题：`生成摘要列表`
- 选项使用整行卡片式按钮，右侧显示进入箭头，避免仅像普通文字。
- 选项：
  - `新文章优先`：`按发布时间从新到旧生成，速度最快`
  - `AI 推荐`：`先读取摘要候选，再挑选更值得通勤收听的文章`，带 `推荐` 标签
- 点击任一选项后，在原弹窗内替换为生成中卡片。

如果来源未配置，仍沿用现有生成前校验并提示：`请先配置摘要来源`。

### 摘要模式有旧结果

切到摘要模式且已有上次生成结果时，不自动覆盖，直接保留当前队列。

播放卡展示当前摘要标题、来源、`n/n` 和播放控制；不再单独显示“上次生成”一行，也不单独展示规则卡。

右上角刷新图标用于重新生成；点选时打开同一个生成方式弹窗。

旧结果信息在弹窗顶部作为第一部分展示，避免长句堆叠：

- 分区标题：`当前摘要列表`
- 生成时间：`2026-04-24 08:12`
- 内容规模：`16 篇 · 约 12,345 字`
- 时长：`约 28 分钟 / 目标 30 分钟`

旧结果信息下方增加第二部分标题 `生成新摘要列表`，再用卡片式按钮提供 `新文章优先` 和 `AI 推荐` 两种生成方式，不再额外套第二个确认弹窗。

### 生成中反馈

点击生成方式后，弹窗不立即关闭，而是把生成方式区域替换成单张加载卡片。

- `新文章优先`：`摘要列表生成中…` / `正在选择新文章并准备播放队列`
- `AI 推荐`：`AI 推荐生成中…` / `正在调用已配置的 AI 服务挑选文章，可能需要几十秒`

加载期间禁用重复生成。底部按钮从 `取消` 改为 `关闭`，只收起弹窗，不中断后台生成；完成后关闭弹窗并沿用 toast 反馈。

### 生成结果反馈

- 成功：`已生成 28 分钟的摘要列表`
- 不足：`可用摘要不足 30 分钟，已生成 12 分钟`
- 为空：`所选来源下没有可朗读的摘要文章`

### 播放文案

摘要模式每篇文章朗读内容：

- `标题。来源。摘要内容。`

队列项仍指向原文章，便于从面板打开正文精读。

## 设置项设计

在交互设置或 AI/TTS 相关设置区新增 `摘要模式` 小节。

设置项：

- `摘要来源`
  - 说明：`选择用于生成摘要列表的订阅分组和订阅源`
  - 入口：打开来源选择页面或弹窗。
- `摘要时长`
  - 说明：`按预计朗读时长生成摘要队列`
  - 默认：`30 分钟`
  - 可选：`15 分钟 / 30 分钟 / 45 分钟 / 60 分钟`
- `听完摘要后标记为已读`
  - 说明：`摘要自然播放完成后自动标记为已读`
  - 默认：关闭。

### AI 设置页分组

AI 设置页保留 `模型服务` 作为基础配置区，并将原 `摘要与提示词` 拆成三个短分区：

- `模型服务`：API 地址、API Key、模型选择、测试连接。测试连接使用当前模型发起一次轻量 chat completion 请求，不依赖 `/models` 接口。
- `摘要`：摘要提示词、后台预生成摘要、每次预生成篇数、同步时补齐历史未读摘要、立即补齐历史未读摘要。
- `翻译`：翻译提示词。
- `问答`：问答提示词。

`打开文章时自动摘要` 属于订阅源级配置，不放在 AI 设置页主分区。测试连接不新增持久化设置；现有 AI 配置和摘要模式偏好已随 DataStore 偏好 JSON 进入备份导入导出。

## 数据设计

### 队列模式

新增 TTS 队列模式：

- `Normal`：全文模式。
- `Commute`：摘要模式，内部命名暂沿用通勤实现名。

控制器对外暴露当前模式和当前模式下的队列状态。切换模式时：

- 暂停当前播放内容。
- 切换当前展示和操作的队列状态。
- 不清空另一个模式的队列。

### 队列项内容类型

为 TTS 队列项增加播放内容类型：

- `FullArticle`：全文朗读，全文模式默认。
- `AiSummary`：摘要朗读，摘要模式固定使用。

摘要队列项需要持久化摘要播放内容，避免生成后文章摘要变化或被清空导致旧队列不可播放。

### 摘要列表元信息

摘要队列保存生成元信息：

- `generatedAt`：生成时间。
- `estimatedDurationMinutes`：预计总时长。
- `targetDurationMinutes`：目标时长。
- `itemCount`：生成条数。
- `generationMode`：生成策略，区分 `新文章优先` 与 `AI 推荐`。

这些信息用于摘要模式弹窗中的当前列表信息展示。

### 设置持久化

新增偏好项：

- `commuteBriefGroupIds`：已选分组 id 列表。
- `commuteBriefFeedIds`：已选订阅源 id 列表。
- `commuteBriefDurationMinutes`：目标时长，默认 30。
- `commuteBriefMarkReadOnComplete`：摘要播放完成后是否标已读，默认 false。

第一版可用 JSON 字符串保存 id 列表，避免引入额外表结构。

## 生成规则

生成时提供两个策略：

- `新文章优先`：现有快速路径，按发布时间从新到旧累加到目标时长附近。
- `AI 推荐`：先按发布时间新到旧取候选池，再让 AI 读取候选摘要并输出推荐文章顺序。

基础流程：

1. 读取摘要来源配置。
2. 查询来源下未读文章。
3. 过滤 `aiSummary` 为空的文章。
4. 将 `标题 + 来源 + 摘要` 转成可朗读 HTML，并估算每篇摘要时长。
5. 按生成策略选择文章。
6. 按目标时长截断或补齐。
7. 替换摘要模式队列并保存生成元信息。

`AI 推荐` 策略规则：

- 先按发布时间新到旧取约 `目标时长 × 3` 的候选，最多 60 篇。
- AI 只读取候选文章的标题、来源、发布时间、已有摘要和预计朗读时长，不读取全文，也不生成新摘要。
- AI 输出推荐 `articleId` 顺序，客户端按该顺序生成队列。
- 如果 AI 推荐不足目标时长，用未选候选按新文章优先补齐。
- AI 推荐调用已配置的 AI 服务，最多等待约 60 秒。
- 如果 AI 服务未配置、超时、调用失败或输出无法解析，则回退到 `新文章优先`，并提示用户。

生成不自动补摘要，也不自动修改文章已读状态。

## 播放完成处理

当摘要模式下某篇摘要自然播放完成：

- 如果 `听完摘要后标记为已读` 关闭：只推进到下一条。
- 如果开关开启：将该文章标记为已读，再推进到下一条。
- 手动跳过、上一条、切换模式、暂停或清空不触发自动已读。

## 实施拆分

### 阶段 1：队列模型与持久化

- 扩展 `TtsQueueItem`，增加播放内容类型和摘要内容字段。
- 扩展 `TtsQueueSnapshot`，保存全文队列、摘要队列、当前模式和摘要列表元信息。
- 调整 `TtsQueueController`，支持模式切换和按模式操作队列。
- 保持旧 snapshot 兼容：旧 `articleIds` 迁移为全文模式队列。

### 阶段 2：摘要播放内容

- 调整 `TtsQueueArticleRepository`，按队列项内容类型解析播放内容。
- 全文模式继续走全文 HTML。
- 摘要模式使用持久化的 `标题 + 来源 + 摘要` HTML。
- 保持媒体通知、耳机控制、进度和分段跳转继续复用现有逻辑。

### 阶段 3：摘要队列生成

- 在 ViewModel 或独立 use case 中实现 `generateCommuteBriefQueue`。
- 查询已选分组和订阅源下未读且已有摘要的文章。
- 支持 `新文章优先` 和 `AI 推荐` 两种生成策略。
- `AI 推荐` 先取 3 倍时长候选并限制最多 60 篇，再调用 AI 返回推荐顺序。
- 写入摘要队列并保存生成元信息。
- 处理空结果、不足时长、AI 失败回退、生成中 loading 和替换旧结果后的反馈。

### 阶段 4：播放列表 UI

- 将播放列表标题改成模式下拉。
- 全文模式沿用现有 UI。
- 摘要模式标题改为 `摘要模式`，右上角刷新用于生成/重新生成摘要列表。
- 摘要模式空态提示收进播放卡，旧结果不再单独展示规则或“上次生成”条。
- 生成弹窗分为 `当前摘要列表` 与 `生成新摘要列表` 两段，旧结果信息展示生成时间、篇数、字数和时长。
- 摘要模式队列项显示 `摘要 · 来源` 信息。

### 阶段 5：设置项与来源选择

- 增加摘要模式设置项和中文/英文文案。
- 增加时长选择弹窗。
- 增加来源选择入口，支持分组和订阅源多选。
- 增加自动已读开关。
- 将新增设置纳入备份恢复。

### 阶段 6：验证与收尾

- 增加队列 reducer / controller 单元测试。
- 增加摘要生成规则测试：来源过滤、摘要过滤、新文章排序、时长截断。
- 编译验证 `:app:compileGithubAiDebugKotlin`。
- 根据实际改动更新 release 文档或 handoff 文档。

## 验证点

- 全文队列和摘要队列互不污染。
- 旧 snapshot 可以正常恢复到正常队列。
- 摘要模式只包含已有摘要的未读文章。
- 默认时长为 30 分钟，设置后按新时长生成。
- 新文章优先排序稳定。
- 有旧摘要列表结果时切换模式不自动覆盖。
- 重新生成弹窗展示当前摘要列表的生成时间、篇数、字数和时长，并提供生成中 loading 状态。
- 摘要自然播放完成后，只有开关开启才标记已读。
- 手动跳过不标记已读。
- 通知栏和耳机上一条/下一条在两种模式下都能控制当前队列。

## 风险与后续

- 队列控制器从单队列扩展为双队列，需特别注意旧 snapshot 兼容和播放状态切换。
- 摘要来源多选 UI 可能比核心生成逻辑更费时，必要时可先落地分组选择，再补单独订阅源选择。
- 摘要时长估算只能近似；第一版使用现有字数转时长规则即可。
- 后续可扩展：无摘要时后台补摘要、AI 重要性排序、多源聚类去重、按收听历史自动推荐来源。
