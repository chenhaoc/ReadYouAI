# 通勤简报模式设计

日期：2026-04-24

## 目标

- 为通勤路上的科技新闻收听提供一个低操作成本入口。
- 在现有 TTS 播放列表基础上增加 `正常模式 / 通勤模式` 切换。
- 通勤模式只朗读已有 AI 摘要，避免默认朗读全文导致信息密度过低。
- 保留旧通勤结果，避免切换模式或误触时覆盖已生成的摘要队列。

## 非目标

- 不在第一版做 AI 重要性排序、聚类去重或跨来源主题合并。
- 不为没有摘要的文章自动生成摘要。
- 不改变现有阅读页、列表页的单篇 `加入播放列表 / 立即播放` 行为。
- 不新增一套独立播放器；继续复用现有 TTS 播放、通知栏和耳机控制链路。

## 已确认产品规则

- 通勤来源支持配置多个订阅分组和多个单独订阅源。
- 只扫描通勤来源下的未读文章。
- 只加入已有 AI 摘要的文章；没有摘要的文章跳过。
- 默认通勤时长为 30 分钟，并提供配置项。
- 默认排序为新文章优先。
- `听完摘要后标记为已读` 做成开关，默认关闭。
- 正常队列和通勤队列分开保存，共用底层 TTS 播放服务。

## 交互设计

### 播放列表面板

将现有播放列表标题改成可切换模式的标题：

- 正常模式：`播放列表 ▾`
- 通勤模式：`通勤简报 ▾`
- 下拉选项：
  - `正常模式`
  - `通勤模式`

### 正常模式

- 保持现有播放列表行为。
- 继续显示当前播放卡片、定时播放、清空、队列项排序、删除和打开文章。
- 普通文章加入队列时只影响正常模式队列。

### 通勤模式空状态

切到通勤模式且没有旧结果时，播放卡直接提示：

- 标题：`还没有通勤简报`
- 提示：`请点击右上角生成`

右上角保留刷新图标；点击后直接生成。

如果来源未配置，仍沿用现有生成前校验并提示：`请先配置通勤简报来源`。

### 通勤模式有旧结果

切到通勤模式且已有上次生成结果时，不自动覆盖，直接保留当前队列。

播放卡展示当前摘要标题、来源、`n/n` 和播放控制；不再单独显示“上次生成”一行，也不单独展示规则卡。

右上角刷新图标用于重新生成；点选时弹确认：

- 标题：`重新生成通勤简报？`
- 内容：`当前通勤简报生成于 2026-04-24 08:12，16 篇，约 12,345 字，约 28 分钟（目标 30 分钟），重新生成会替换它。`
- 按钮：`替换并生成` / `取消`

### 生成结果反馈

- 成功：`已生成 28 分钟的通勤简报`
- 不足：`可用摘要不足 30 分钟，已生成 12 分钟`
- 为空：`所选来源下没有可朗读的摘要文章`

### 播放文案

通勤模式每篇文章朗读内容：

- `标题。来源。摘要内容。`

队列项仍指向原文章，便于从面板打开正文精读。

## 设置项设计

在交互设置或 AI/TTS 相关设置区新增 `通勤简报` 小节。

设置项：

- `通勤简报来源`
  - 说明：`选择用于生成通勤摘要队列的订阅分组和订阅源`
  - 入口：打开来源选择页面或弹窗。
- `通勤简报时长`
  - 说明：`按预计朗读时长生成摘要队列`
  - 默认：`30 分钟`
  - 可选：`15 分钟 / 30 分钟 / 45 分钟 / 60 分钟`
- `听完摘要后标记为已读`
  - 说明：`摘要自然播放完成后自动标记为已读`
  - 默认：关闭。

## 数据设计

### 队列模式

新增 TTS 队列模式：

- `Normal`：正常模式。
- `Commute`：通勤模式。

控制器对外暴露当前模式和当前模式下的队列状态。切换模式时：

- 暂停当前播放内容。
- 切换当前展示和操作的队列状态。
- 不清空另一个模式的队列。

### 队列项内容类型

为 TTS 队列项增加播放内容类型：

- `FullArticle`：全文朗读，正常模式默认。
- `AiSummary`：摘要朗读，通勤模式固定使用。

通勤队列项需要持久化摘要播放内容，避免生成后文章摘要变化或被清空导致旧队列不可播放。

### 通勤元信息

通勤队列保存生成元信息：

- `generatedAt`：生成时间。
- `estimatedDurationMinutes`：预计总时长。
- `targetDurationMinutes`：目标时长。
- `itemCount`：生成条数。

这些信息用于通勤模式顶部状态展示。

### 设置持久化

新增偏好项：

- `commuteBriefGroupIds`：已选分组 id 列表。
- `commuteBriefFeedIds`：已选订阅源 id 列表。
- `commuteBriefDurationMinutes`：目标时长，默认 30。
- `commuteBriefMarkReadOnComplete`：摘要播放完成后是否标已读，默认 false。

第一版可用 JSON 字符串保存 id 列表，避免引入额外表结构。

## 生成规则

生成时按以下顺序处理：

1. 读取通勤来源配置。
2. 查询来源下未读文章。
3. 过滤 `aiSummary` 为空的文章。
4. 按发布时间新到旧排序。
5. 将 `标题 + 来源 + 摘要` 转成可朗读 HTML。
6. 按摘要字数估算朗读时长，累加到目标时长附近停止。
7. 替换通勤模式队列并保存生成元信息。

生成不自动补摘要，也不自动修改文章已读状态。

## 播放完成处理

当通勤模式下某篇摘要自然播放完成：

- 如果 `听完摘要后标记为已读` 关闭：只推进到下一条。
- 如果开关开启：将该文章标记为已读，再推进到下一条。
- 手动跳过、上一条、切换模式、暂停或清空不触发自动已读。

## 实施拆分

### 阶段 1：队列模型与持久化

- 扩展 `TtsQueueItem`，增加播放内容类型和摘要内容字段。
- 扩展 `TtsQueueSnapshot`，保存正常队列、通勤队列、当前模式和通勤元信息。
- 调整 `TtsQueueController`，支持模式切换和按模式操作队列。
- 保持旧 snapshot 兼容：旧 `articleIds` 迁移为正常模式队列。

### 阶段 2：摘要播放内容

- 调整 `TtsQueueArticleRepository`，按队列项内容类型解析播放内容。
- 正常模式继续走全文 HTML。
- 通勤模式使用持久化的 `标题 + 来源 + 摘要` HTML。
- 保持媒体通知、耳机控制、进度和分段跳转继续复用现有逻辑。

### 阶段 3：通勤队列生成

- 在 ViewModel 或独立 use case 中实现 `generateCommuteBriefQueue`。
- 查询已选分组和订阅源下未读且已有摘要的文章。
- 按新文章优先排序并按目标时长截断。
- 写入通勤队列并保存生成元信息。
- 处理空结果、不足时长和替换确认后的生成反馈。

### 阶段 4：播放列表 UI

- 将播放列表标题改成模式下拉。
- 正常模式沿用现有 UI。
- 通勤模式标题改为 `通勤简报`，右上角刷新用于生成/重新生成。
- 通勤模式空态提示收进播放卡，旧结果不再单独展示规则或“上次生成”条。
- 重新生成前增加确认弹窗，内容包含生成时间、篇数、字数和时长。
- 通勤模式队列项显示 `摘要 · 来源` 信息。

### 阶段 5：设置项与来源选择

- 增加通勤简报设置项和中文/英文文案。
- 增加时长选择弹窗。
- 增加来源选择入口，支持分组和订阅源多选。
- 增加自动已读开关。
- 将新增设置纳入备份恢复。

### 阶段 6：验证与收尾

- 增加队列 reducer / controller 单元测试。
- 增加通勤生成规则测试：来源过滤、摘要过滤、新文章排序、时长截断。
- 编译验证 `:app:compileGithubAiDebugKotlin`。
- 根据实际改动更新 release 文档或 handoff 文档。

## 验证点

- 正常队列和通勤队列互不污染。
- 旧 snapshot 可以正常恢复到正常队列。
- 通勤模式只包含已有摘要的未读文章。
- 默认时长为 30 分钟，设置后按新时长生成。
- 新文章优先排序稳定。
- 有旧通勤结果时切换模式不自动覆盖。
- 重新生成前有替换确认，且确认文案展示生成时间、篇数、字数和时长。
- 摘要自然播放完成后，只有开关开启才标记已读。
- 手动跳过不标记已读。
- 通知栏和耳机上一条/下一条在两种模式下都能控制当前队列。

## 风险与后续

- 队列控制器从单队列扩展为双队列，需特别注意旧 snapshot 兼容和播放状态切换。
- 通勤来源多选 UI 可能比核心生成逻辑更费时，必要时可先落地分组选择，再补单独订阅源选择。
- 摘要时长估算只能近似；第一版使用现有字数转时长规则即可。
- 后续可扩展：无摘要时后台补摘要、AI 重要性排序、多源聚类去重、按通勤历史自动推荐来源。
