# TTS 播放器美化与定时播放设计

## 背景
TTS 播放列表已经从单纯的队列视图，演进成承接播放控制、播放进度、定时停止和当前文章跳转的统一入口。当前实现已经覆盖队列页内卡片、底部浮动 MiniPlayer、状态栏前台控件三层播放体验，需要用一份落地文档把最终形态收敛下来。

## 已落地目标
- 在播放列表顶部保留统一的 `播放列表` 标题和定时播放入口。
- 在当前播放卡片中集中承载标题、来源、序号、播放控制和进度条。
- 在 MiniPlayer 中复用相同的控制语义，避免两套播放交互。
- 提供倒计时停止和“当前音频结束后停止”两类睡眠定时。
- 提供状态栏播放控件，并保证后台续播与前台控制同步。

## 当前界面结构

### 播放列表头部
```text
[播放列表]                 [定时播放▼] [清空]
```

### 当前播放卡片
```text
[标题]
[来源]                         [x/x]

 [上一段] [上一条] [播放/暂停] [下一条] [下一段]

00:05 ───●────────────── 14:20
```

### MiniPlayer
- 复用当前播放卡片的核心控制逻辑。
- 保留更轻量的外壳和悬浮入口，不重复展示定时播放菜单。
- 在阅读页、信息流和订阅源共用同一套队列状态。

## 交互约束

### 控制按钮
- 顺序固定为：`上一段 / 上一条 / 播放暂停 / 下一条 / 下一段`。
- 播放暂停是主操作，视觉层级最高。
- 上一段和下一段只在当前文章存在可跳转分段时可用。
- 点击当前播放卡片标题会先关闭播放列表，再跳转到当前文章。

### 时间轴
- 时间轴位于控制区下方，与控制区保持紧凑的垂直关系。
- 左侧展示当前时间，右侧展示总时长。
- 拖动和点击 seek 继续基于现有分段时长估算逻辑。

### 定时播放
- 入口位于播放列表头部。
- 支持：`关闭`、`5 min`、`10 min`、`15 min`、`30 min`、`当前音频结束`。
- 倒计时到点后停止播放并结束前台服务。
- “当前音频结束”会拦截自动进入下一篇。
- 再次选择新选项会覆盖旧定时。

## 状态与实现

### 状态来源
- 统一由 `TtsQueueController` 管理播放状态、当前条目、分段索引、进度估算和睡眠定时。
- `TtsQueueOverlayViewModel` 负责把队列状态暴露给根级播放列表宿主和浮动按钮。

### 组件拆分
- `TtsQueueSheet` 承载播放列表和当前播放卡片。
- `TtsPlaybackControlsRow` 统一控制按钮布局。
- `TtsPlaybackTimelineRow` 统一时间轴和时间文本。
- `TtsSleepTimerDropdown` 承载睡眠定时入口。
- `TtsFloatingPlayerButton` 承载阅读场景下的 MiniPlayer 入口。

### 当前 UI 取舍
- 播放列表标题下方不再重复展示 `x 项` 统计，保留卡片中的 `x/x` 序号即可。
- 当前播放卡片允许使用更突出的容器色，以便和普通列表项区分。
- 根级播放列表外壳使用较收敛的横向和底部留白，兼顾屏幕圆角和内容密度。

## 非目标
- 不实现按秒快进或快退。
- 不实现跨进程精确恢复倒计时。
- 不在 MiniPlayer 里重复提供睡眠定时入口。
- 不调整普通队列项的交互模型，只保留播放、排序和删除。

## 验证要点
- 播放列表、MiniPlayer、状态栏控件的播放状态保持一致。
- 睡眠定时能正确停止播放，并在后台继续生效。
- 点击当前播放标题会先收起播放列表，再跳转文章。
- 阅读时长估算、当前时间和总时长展示与当前分段进度一致。
